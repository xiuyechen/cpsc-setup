Setting up Claude Code for this course

You will do this once, at the start of the workshop. It takes about fifteen minutes. No programming experience is assumed — if you have never opened a terminal before, this page is written for you.

What you are actually doing

By the end you will have two separate ways to use Claude Code on your laptop:

  • The shared class account, which you will use in a moment to help with setup.
  • A course connection of your own, which you will start with the command claude-edu. This is the one you use for assignments.

Keeping them separate matters. Your own personal Claude account, if you have one, stays completely untouched.

Four words to know first

Terminal
An app on your computer where you type commands as text instead of clicking buttons. On a Mac it is called Terminal and lives in Applications › Utilities. It looks intimidating and is mostly harmless. You can always close the window and start over.
API key
A long password that identifies you to a service. Yours is personal to you. Like a password, you do not share it or post it anywhere.
Environment variable
A named setting that programs on your computer can read — a sticky note that programs know to look at. We will set a few so Claude Code knows which service to talk to.
Shell profile file
A file the terminal reads every time you open a new window. Anything written in it is set up automatically, so you do not have to retype it. This is where your settings will live.

Open the terminal

On a Mac, press ⌘ Space, type Terminal, and press Return. On Windows, open Ubuntu (WSL2) rather than PowerShell.

You should see

A mostly empty window with a line of text ending in $ or %, and a blinking cursor. That is the prompt, waiting for you.

Start Claude Code on the class account

Your instructor will give you the sign-in details for the shared class account. Start it by typing:

$ claude

What this does: opens Claude Code, an assistant that can read and write files on your computer and run commands for you. It will ask you to sign in the first time.

You should see

A welcome banner, then a prompt where you can type in plain English.

Get your personal key

Go to the class key page your instructor gave you and copy your key. It is a short string of letters and numbers.

About your key

This key is yours alone. It has a spending limit and stops working at the end of the term, which is why the next step is safe — but treat it like a password anyway. Do not post it in a chat, an email, or a shared document.

It will also be saved in Claude Code's own record of this conversation, in a file on your laptop. That is expected and fine. Just do not copy it anywhere else.

Ask Claude Code to set it up

In the Claude Code session you started in the previous step, paste the line below, replacing YOUR-KEY with the key you just copied. Claude Code will read the instructions and do the setup for you.

# paste this to Claude Code, not to the terminal
Fetch https://xiuyechen.github.io/cpsc-setup/agent-setup.txt
and follow it exactly. My key is: YOUR-KEY

What this does: Claude Code fetches the course setup instructions, works out which shell you have, writes a small settings file, and adds one line to your shell profile so the terminal loads it automatically. It will show you each change before making it.

You should see

Claude Code may first ask permission to fetch the page — say yes. Then it will report the file it created (its name ends in .local.portkey), the line it added to your profile, and a few checks confirming everything is in place.

If it cannot fetch the page

Some setups block the fetch. Instead, open the instructions link in your browser, select all the text, and paste the whole thing into Claude Code followed by your key on the last line. It works exactly the same way.

When it finishes, type /exit to leave Claude Code.

Now close this terminal window entirely

Close the whole window — do not just type a new command in it.

This is the step people skip, and skipping it makes the next step fail. Your new settings are only read when a terminal starts. The window you have open right now started before those settings existed, so it does not know about them. A fresh window will.

Open a brand new terminal window before continuing.

Test the course connection

In your new terminal window, type:

$ claude-edu

What this does: starts Claude Code using the course connection instead of a personal account. It is the same program — only the connection behind it differs.

You should see

The Claude Code welcome banner, and somewhere in it the words API Usage Billing. That phrase is how you know the course connection is working. If you do not see it, something did not take — check the troubleshooting below.

Say hello

Type a short message and press Return:

Hello! Which model are you running on?
You should see

A normal reply. You are set up. From now on, use claude-edu for coursework and plain claude for anything personal.

If something went wrong

Nearly every problem here is one of these five. Open the one that matches.

“claude-edu: command not found”

This is the most common one, and it almost always means you are still in the old terminal window.

Fix: close the terminal window completely and open a new one, then try claude-edu again.

If a brand new window still says this, your settings may have gone into the wrong profile file. See the next item.

Nothing happens in a new window — wrong profile file

Different shells read different startup files, so settings written to the wrong one are never loaded.

Start claude again on the class account and tell it:

claude-edu isn't found in a new terminal.
Check which shell I actually use and whether the
setup line went into the right profile file.

It can detect the problem and move the line for you.

“Permission denied” when running chmod

This usually means the file is not where the command expected, or the path was mistyped. Check it exists:

$ ls -la ~/.zshrc.local.portkey

If you see No such file or directory, the setup file was not created — go back to step 4. If the file is listed but the command still fails, ask Claude Code on the class account to fix the file's permissions for you.

No “API Usage Billing” in the banner

Claude Code started, but on a personal or class account rather than the course connection. The settings did not reach it.

Confirm the settings are visible in your new terminal:

$ echo $PORTKEY_CONFIG

If that prints nothing, the profile line is missing or in the wrong file — see the wrong-profile-file item above. If it prints something that starts with pc-, the settings are loading and the problem is elsewhere; show your instructor.

An error mentioning a key, or 401 / 403

The key was probably pasted with a missing character or an extra space. Re-copy it from the class key page and ask Claude Code on the class account to update it.

If it still fails, your key may have hit its spending limit or expired. Ask your instructor for a fresh one.

Two habits worth having

  • Use claude-edu for coursework, plain claude for everything else. They are separate on purpose.
  • Work in focused stretches. Long idle gaps mid-session make Claude Code re-send everything it already knows, which is slower and uses more of your budget. Finishing a task and then stepping away is better than leaving a session open for hours.

Stuck for more than ten minutes? Stop and ask — setup problems are not a test of anything, and someone else in the room has almost certainly hit the same one.
